# Мейнфрейм

Личный ИИ-агент, который работает на тебя круглосуточно. Живёт на твоём сервере, работает на моделях MiniMax, управляется из бота MAX и веб-пульта.

## Что он делает

- **Входящие.** Читает личные чаты MAX, рабочие группы и каналы, почту и комментарии. Неважное откладывает, важное приносит карточкой с готовым черновиком ответа. Отправляет только после твоего «да».
- **Задачи голосом и текстом.** Пишешь или говоришь боту, он делает: в терминале, в коде, в файлах, в календаре, в почте. Сессия по каждому проекту продолжается с того же места.
- **Сводки.** Утром и вечером: встречи, напоминания, кто ждёт ответа, траты за день, что вышло в соцсетях.
- **Соцсети.** Студия постов в твоём стиле под MAX, LinkedIn, Instagram, Threads, TikTok. Календарь, банк идей, наблюдение за конкурентами и черновики по их удачным постам.
- **Финансы.** Траты из писем банков, чеки фото, остатки по скриншотам, итог в одной валюте.
- **Память.** Помнит тебя, твои правила, людей и решения во всех разговорах. Поиск по всей истории: «что Аня писала про договор», «что решили про цену в октябре».
- **Расписание.** Любые задачи по cron, итог приходит в бот.
- **Аудитория.** Список чатов и каналов, где бот состоит, и людей, которых он там видит: команда `/audience`.

## Как устроен

```
              Бот MAX и веб-пульт (https)
                          │
   ┌──────────── сервер, работает всегда ────────────┐
   │ шлюз на Node · SQLite · очередь · расписание    │
   │ исполнитель на MiniMax · память · поиск          │
   │ чаты и каналы MAX · соцсети · финансы           │
   └───────────────▲─────────────────────────────────┘
                   │ SSH-туннель (его открывает Mac)
   ┌───────────────┴─── твой Mac, когда включён ─────┐
   │ Почта, Календарь, Заметки, Напоминания          │
   │ управление Mac · расшифровка голосовых          │
   │ сессии по проектам, чьи файлы лежат на Mac      │
   └─────────────────────────────────────────────────┘
```

Пока Mac выключен, всё остальное работает, а задачи для Mac ждут его и запускаются сами.

## Что понадобится

1. **Ключ MiniMax API** — [platform.minimax.io](https://platform.minimax.io), международный регион (`api.minimax.io`). Актуальные модели: `MiniMax-M3.1-Flash`, `MiniMax-M3`.
2. **Сервер** с Ubuntu 22.04 или 24.04, от 2 ГБ памяти.
3. **Бот в MAX** — MAX → Чат-боты → создать; токен в настройках бота.
4. **Mac** по желанию: для почты, календаря, голосовых и проектов с кодом.

## Установка

```bash
git clone https://github.com/pavelvladimirovich258614-sys/Maxframe.git
cd Maxframe
npm ci
cp .env.example .env
```

Заполни в `.env` как минимум:

```bash
MAX_BOT_TOKEN=...          # токен бота MAX
MINIMAX_API_KEY=...        # ключ MiniMax
```

Затем:

```bash
npm start
```

**Первые шаги.**

1. Открой пульт на `http://127.0.0.1:7777` — там есть личная ссылка с токеном и код привязки.
2. Напиши боту в MAX `/start КОД` (или нажми «Начать» в карточке бота с кодом в ссылке).
3. Расскажи о себе: «запомни, что я…», «запомни, что пишу без длинных тире».
4. Заполни базу знаний для ответов людям: папка `kb`, пример в `kb/примеры`.
5. Если нужен вебхук вместо опроса событий — задай `PUBLIC_URL` (https, порт 443) и `MAX_LONG_POLLING=0`.

Проверка на живых сервисах — по шагам в [MIGRATION-MAX.md](MIGRATION-MAX.md#как-выполнить-живую-проверку).

## Настройки

Всё личное хранится в `.env` и в папке памяти, не в коде. Главное:

| Переменная | Что это |
|---|---|
| `MAX_BOT_TOKEN` | токен бота MAX |
| `MAX_OWNER_ID` | твой user_id в MAX (не обязателен: бот привяжется по коду) |
| `MAX_WEBHOOK_SECRET` | секрет для webhook (MAX присылает его в `X-Max-Bot-Api-Secret`) |
| `MAX_LONG_POLLING` | `1` — получать события опросом (локально), `0` — webhook (production) |
| `MAX_ALLOWED_CHATS` | чаты, где бот отвечает; пусто — все, где он состоит |
| `MINIMAX_API_KEY` | ключ MiniMax |
| `MINIMAX_MODEL` | модель исполнителя, по умолчанию `MiniMax-M3.1-Flash` |
| `MINIMAX_DISPATCH_MODEL` | модель для коротких задач (диспетчер, черновики) |
| `OWNER_NAME` | как тебя зовут |
| `SOCIAL_MAX_CHAT_ID` | числовой chat_id твоего канала в MAX |
| `OFFER_URL`, `OFFER_CTA` | куда ведут посты и как это назвать |
| `PERMISSION_MODE` | права агента: `bypassPermissions`, `ask`, `deny` |
| `INBOX_BURST_MS` | сколько ждать остальные строки сообщения, прежде чем сделать карточку (по умолчанию 2500) |
| `AUTO_FORWARD`, `AUTO_REPLY` | авто-режим для входящих (по умолчанию выключен) |

Полный список с пояснениями в `.env.example`.

## Ограничения MAX, о которых стоит знать

- **Бот видит только то, где он состоит.** У MAX нет доступа к личному аккаунту: сообщения из личных чатов, не адресованные боту, и чаты, где бот не состоит, недоступны. Мейнфрейм не притворяется, что умеет больше.
- **В группе нужна админка.** Бот получает события о сообщениях в группе, только если он администратор с правом `read_all_messages`.
- **Списка чатов у API нет.** `GET /chats` удалён в июне 2026. Набор чатов мейнфрейм собирает из событий и из `MAX_ALLOWED_CHATS`.
- **Курсор истории — время, а не id.** `GET /messages` ждёт в `after` время в секундах; по id сообщения он не фильтрует.
- **Webhook и опрос нельзя вместе.** Для production — только webhook на порту 443 с сертификатом доверенного центра или Минцифры. Секрет проверяется постоянным временем.
- **Просмотры видны не везде.** Число просмотров приходит с сообщением канала, но только боту с правом `view_stats`, а MAX выдаёт его владельцу канала. У чужих каналов цифр не будет — метрики не выдумываются.
- **Команда бота** — `PATCH /me/commands`, до 32 команд.
- **Текст сообщения** — до 4000 символов, форматирование только `markdown` или `html` из ограниченного списка тегов.
- **Клавиатура** — только встроенная (`inline_keyboard`), отдельной «клавиатуры ответа» нет.

## Безопасность

- Всё работает на твоём сервере и твоём ключе MiniMax. Данные никуда не уходят, кроме самих сервисов (MiniMax, MAX, Metricool).
- Пульт открывается только тобой: через бота или по личной ссылке с токеном.
- Сообщения людям, публикации, письма и удаление уходят только после твоего подтверждения.
- Сообщения от других людей считаются данными: такая сессия не может публиковать, ставить cron-задачи, слать почту и управлять компьютером.
- Если сообщение попало в сессию без твоего подтверждения (авто-пересылка), оно тем более не может запускать команды, браузер или компьютер.
- Каждую ночь в 03:30 резервная копия базы и памяти, хранится 14 дней.
