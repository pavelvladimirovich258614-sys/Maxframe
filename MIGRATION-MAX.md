# Миграция на MAX и MiniMax: что сделано, что нельзя и почему

Статус: основные сценарии перенесены и покрыты тестами. Проверка с реальными ключами MAX и MiniMax не проводилась — у исполнителя их нет.

## Что было

Проект — личный агент: бот в Telegram, исполнитель на Claude Agent SDK, веб-пульт, входящие из личных чатов и рабочих групп Telegram, почты и каналов, cron-задачи, общая память, поиск по истории, финансы, соцсети.

Исходная схема:

```
Telegram-бот (grammY) ─┐
Telegram-аккаунт ──────┼─► dispatcher ─► agent (Claude Agent SDK) ─► SQLite
почта, календарь ──────┘        │                    │
                                 ▼                    ▼
                            карточки входящих     MCP-серверы
```

## Что стало

```
Бот MAX ──────────────┐
MAX-каналы и группы ──┼─► dispatcher ─► agent (MiniMax) ─► SQLite
почта, календарь ─────┘        │              │
        webhook / long polling  │              ├─ файлы, поиск, терминал
        POST /max/webhook       │              ├─ инструменты мейнфрейма
                                 │              └─ MCP-серверы из mcp.json
                                 ▼
                            карточки входящих
```

## Решения по каждому слою

### Исполнитель: Claude Agent SDK → MiniMax

Claude Agent SDK давал сессии, инструменты, MCP, хуки, `resume`, режимы прав и структурированные ответы. Замена одного URL модели тут не работает, поэтому исполнитель написан заново, но с теми же контрактами.

| Что давал SDK | Как сделано сейчас |
|---|---|
| сессия проекта, продолжение диалога | история в SQLite (`agent_messages`) по `projects.session_id`; у проекта без сессии создаётся своя |
| инструменты Read/Write/Edit/Grep/Glob/Bash | `src/agent-tools.js`: `read_file`, `write_file`, `edit_file`, `search_files`, `list_files`, `run_command` |
| MCP-серверы из `mcp.json` | `src/mcp.js`: мост через MCP SDK, имя инструмента `mcp__<сервер>__<инструмент>` |
| встроенный MCP-сервер `mainframe` | те же 20 инструментов, но обычные функции в том же реестре |
| хуки (PreToolUse/PostToolUse) | проверка папки и секретов в самих инструментах, журнал вызовов в `run_events` |
| `permissionMode` | `bypassPermissions` / `ask` / `deny` в `config.permissionMode` |
| `disallowedTools` для недоверенных | `INBOX_BLOCKED` в `src/agent.js`: сессия, начатая чужим сообщением, не публикует, не ставит cron, не шлёт почту и не управляет компьютером |
| `outputFormat` со схемой | `structured()`: модель зовёт один инструмент `submit_result` со схемой ответа; если модель ответила текстом, JSON вытаскивается из него |
| отмена задачи | `AbortController` + `signal` в запросе MiniMax, `stopRun` работает как раньше |
| поток событий | `run_events` (`text`, `tool`, `error`, `system`), шина `bus` |

Важная деталь MiniMax: у моделей с размышлением рядом с `content` лежит `reasoning_content`. Ответ модели возвращается в диалог без изменений — обрезанный `reasoning_content` ломает многошаговые вызовы инструментов.

### Транспорт: Telegram → MAX

- Базовый URL `https://platform-api2.max.ru`, токен в заголовке `Authorization` **без** `Bearer`. Токен в query не поддерживается.
- `chat_id` у `POST /messages` — это query-параметр, получатель не входит в тело.
- `GET /chats` удалён в июне 2026. Список чатов и каналов мейнфрейм собирает из событий (`max_chats`) и из `MAX_ALLOWED_CHATS`.
- Webhook: `POST /subscriptions` с `url`, `secret` и `update_types`. MAX присылает секрет в `X-Max-Bot-Api-Secret`; проверка постоянным временем. Повторная доставка дедуплицируется по id события (`max_updates`).
- Long polling `GET /updates` — только для локальных запусков. Одновременно с webhook он не работает, поэтому режим выбирается переменной `MAX_LONG_POLLING`.
- Команды бота: `PATCH /me/commands`.
- Кнопки: единственный вид — `inline_keyboard` во вложении сообщения. Отдельной «клавиатуры ответа», как в Telegram, у MAX нет, поэтому меню стало инлайн-кнопками.
- Форматирование: `format: "html"` с ограниченным списком тегов (`b`, `i`, `u`, `s`, `code`, `pre`, `a`, `blockquote`, `mark`, `h1`–`h6`). Теги Telegram (`<tg-time>`, `<blockquote expandable>`) убраны.

### Группы, каналы и аудитория

- Живые события приходят по `message_created` — из них собираются карточки входящих.
- `src/max-chats.js` ведёт реестр чатов (`max_chats`) и участников (`max_members`), умеет читать сообщения (`GET /messages`), метаданные чата (`GET /chats/{id}`) и состав участников (`GET /chats/{id}/members`).
- Команда `/audience` в боте показывает, где бот состоит и кого там видит.
- `src/groups.js` — страховка: опрос чатов из `MAX_ALLOWED_CHATS`, чтобы не потерять сообщения, пока мейнфрейм был выключен.

### Данные

Существующая база SQLite не удалялась и не перезаписывалась. Добавлены только новые таблицы:

| Таблица | Зачем |
|---|---|
| `max_chats` | чаты и каналы, где состоит бот |
| `max_members` | участники этих чатов: доступная аудитория |
| `agent_messages` | история диалогов исполнителя |
| `max_updates` | обработанные события: защита от повторной доставки |

Старые записи сохранили прежние значения `source` (`telegram`, `group`, `mail`) — код понимает и старые, и новые. Таблица `recall_tg` в `src/recall.js` оставлена с прежним именем и колонками, чтобы накопленные данные не пропали, хотя наполняется теперь разговорами MAX.

## Чего в MAX нет и чем это закрыто

| Возможность Telegram | В MAX | Как в мейнфрейме |
|---|---|---|
| личный аккаунт, все чаты и переписки | нет, только то, где состоит бот | входящие — из чатов с ботом; остальное честно недоступно |
| `list_chats`, поиск каналов по @имени | нет, канал задаётся числовым `chat_id` | конкуренты и канал добавляются по `chat_id` |
| реакции на сообщения | нет | живой прогресс показывается правкой сообщения |
| клавиатура ответа под полем ввода | нет | меню — инлайн-кнопки в сообщении |
| `<tg-time>`, раскрывающиеся цитаты | нет | время пишется текстом, цитата обычным `<blockquote>` |
| удаление и правка любых сообщений | нужно право `delete`/`edit` у бота | включено в `allowedTools` и зависит от прав |
| комментарии к постам | есть только в каналах | поддержано на уровне API, сценарий в UI не перенесён |

Проверки с заглушками (без сети): весь набор выше.

Проверки с реальными сервисами — **не проводились**: нужны `MAX_BOT_TOKEN` и `MINIMAX_API_KEY`. Что стоит проверить первым:

1. `GET /me` — токен бота и домен `platform-api2.max.ru` (сертификат Минцифры в хранилище доверия Node).
2. `GET /updates` — бот получает события (или webhook возвращает 200 и MAX перестаёт повторять доставку).
3. `POST /messages` — текст уходит владельцу, кнопки нажимаются, `message_callback` доходит.
4. Один запуск исполнителя: модель зовёт инструмент, ответ приходит в `run_events`, история сохраняется в `agent_messages` и продолжается во втором сообщении.
5. `structured()` — диспетчер возвращает `action` по схеме.

## Переменные окружения

Полный список с пояснениями — в `.env.example`. Обязательные:

```bash
MAX_BOT_TOKEN=...
MINIMAX_API_KEY=...
```

Для production дополнительно:

```bash
PUBLIC_URL=https://ваш-домен      # https, порт 443
MAX_WEBHOOK_SECRET=...              # 5–256 символов [A-Za-z0-9_-]
MAX_LONG_POLLING=0
```

## Мелочи, которые стоит знать при доработке

- **Время в MAX — в секундах.** `message.timestamp` приходит в Unix-секундах; в базе и в интерфейсе нужны миллисекунды. В `src/max-chats.js` нормализованное сообщение хранит секунды, а пересчёт делается на месте (`m.timestamp * 1000`).
- **Пользователь в `initData` Mini App — это `user.id`,** а в объектах Bot API — `user_id`. Проверка в `src/web.js` принимает оба.
- **У MAX нет ссылки на канал.** Публичный формат URL для канала или поста не документирован, поэтому в интерфейсе показывается `chat_id`.
- **Кнопки в MAX — только встроенные.** Отдельной «клавиатуры ответа» нет: меню и кнопки живут в сообщении.
